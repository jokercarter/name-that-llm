## 2. 当前公开最强的一条链：两阶段 LoRA

来源：`nishantdahal/two-stage-lora-on-the-public-pool`（LB 0.592），被
`kirilltym/two-stage-lora-gaussian-ensemble`（0.594）、
`lightningv08/0-595-two-stage-lora-gaussian-olmo2`（0.595）、
`lightningv08/0-597-two-stage-lora-olmo2-smollm3`（0.597）逐层叠加。

### 2.1 为什么是两阶段

| 训练方式 | 本地 CV（5 折，按 prompt 分组） |
|---|---:|
| n-gram SVC，train + 公开语料 | 0.435 |
| Qwen3-8B LoRA，**只用公开语料**（stage 1） | 0.483 |
| Qwen3-8B LoRA，**stage 1 + stage 2** | **0.569** |
| Qwen3-14B LoRA，stage 1 + stage 2 | 0.569 |
| 上面两个 + n-gram + centered twin + 平衡 | **0.593** |

stage 2 单独贡献 **+0.086**，是整个公开方案里最大的一次跳变。作者的原话是
"stage 1 alone already matches a LoRA trained on the host data"——先用 3.5 万条公开语料
学会"每个模型怎么说话"，再用 2,699 条主办方数据学会"主办方提问时它怎么说话"。

**关键反例**：作者明确写了 *"mixing pool passages back in made it worse"*。也就是说
"公开语料 + 主办方语料混在一次训练里"是**负向操作**，这与当前项目 5 万条混合训练的做法正好相反。

### 2.2 训练配方（可复现）

- 骨干：Qwen3-8B-Base **只取前 24 层**（14B 取前 27 层）。理由是风格在早/中层，最后几层编码主题，
  而测试 prompt 全是新的，主题信息是噪声。
- LoRA：rank 16、alpha 32、dropout 0.05，挂在**所有线性层**上。
- 池化：取第 2/4/6/8/12/16/20/24 层，各过一个 LayerNorm，拼接成 8×4096，再接线性层出 18 类。
- 双头：plain 头 + centered 头。训练时以"同一 prompt 的三元组"为单位（每步 6 组），
  损失 = CE(plain) + CE(centered on 组内中心化特征)。
- stage 1：公开语料 34,940 条，1 epoch，class-weighted CE，lr 1e-4（LoRA）/ 1e-3（头），
  10% warmup + cosine。
- stage 2：主办方 2,699 条，**2 epoch**，lr 5e-5 / 5e-4。
- 推理：把 LoRA 合并进权重（`W ← W + BA·α/r`），不加载 PEFT；关掉最终 RMSNorm（训练时就是 Identity）。

### 2.3 数据池的构造（一个容易被忽略的细节）

14 个公开数据集合并，保留 30–300 词、无 markdown 的单段文本，去重并剔除与训练集相同的文本。
再加一条过滤：**如果某模型在训练集里从不出现某个符号**（比如 Gemini 从不使用 em dash、
Claude 从不使用弯引号），那么该模型公开语料里带这个符号的样本全部丢弃。
最终 34,940 条，每类 1,100–2,700 条。

这条过滤针对的正是"公开语料与主办方生成设置不一致"造成的伪特征。

## 3. 结构层：两个新结论，都推翻了旧假设

### 3.1 隐藏测试集是稀疏的：每 prompt 约 2–3 段

来源：`snaykey/name-that-llm-the-hidden-test-is-sparse`。做法是同一份 notebook 只改
`CENTER_MODE` 提交两次，用分数差反推组大小。LB 实测：

| `CENTER_MODE` | public LB |
|---|---:|
| `off`（不做中心化） | 0.409 |
| `hard`（簇内硬中心化，公开方案的默认做法） | 0.427 |
| `size`（按簇大小加权） | **0.460** |

把 `size − off = +0.051` 代回 CV 表，落在"每 prompt 2 段（+0.030）"与"3 段（+0.059）"之间。

**这意味着**：隐藏测试集不是 18 段/prompt，而是 2–3 段。对一组两段做硬中心化，
`x1 − mean = (x1 − x2)/2`，等于减掉了**另一个作者一半的风格**。所以：

- 组结构类技巧（中心化、distinct-author 解码）在隐藏测试上大约值 **+0.05**，
  而不是全 18 段模拟给出的 **+0.13**；
- 修复只要一行：`w = (n − 1) / (n − 1 + 2)`，n 为簇大小；
- 如果管线是"plain 头之外**再加**一路 centered 证据"（twin 方案），小簇的损害本来就避开了一半，
  按簇大小加权只再涨 +0.002（SE 0.002）——**不值得为它调参**；真正需要改的是"用 centered 头替换 plain 头"的写法。

### 3.2 Gaussian shared-prompt head：把 prompt 效应积分掉

来源：`prvsiyan/the-prompt-is-not-the-author`（0.563 → 0.569，只加这一项）。

模型是生成式的：`Z = μ[class] + P[prompt] + ε`，其中 `P` 是**同组共享**的高斯随机向量，
两个协方差都用 Ledoit–Wolf 收缩、在训练 prompt 上拟合；残差先做 **PCA-128**。

推理时对 2–3 段的小组直接算**精确后验**（三元组枚举 4,896 种组合，带"每个模型至多一次"的约束），
更大的组用 **cavity EM 迭代 5 次**。温度 3.0，在对数概率空间以权重 0.10 加入。

它替代的正是"减样本均值"这个有限样本近似：组越小，样本均值越不可靠，解析积分越占优。

### 3.3 明确报告"没用"的东西

同一批作者在 notebook 里列了负面结果，可以直接跳过：

| 尝试 | 结论 |
|---|---|
| 单纯换更大骨干（14B vs 8B） | 0.569 = 0.569，无收益 |
| seed 平均 | 无收益 |
| 在融合之上再加 family gates | 无收益 |
| **簇内 Hungarian 指派** | **无收益** |
| stage 2 训练更多 epoch | 过拟合 |
| 把公开语料混回 stage 2 | 更差 |

注意第 4 条：当前项目的 PRISM 本质上就是"簇内带容量约束的指派问题"。公开实测说它在
真实 LB 上不涨分——因为它假设每组 18 段，而隐藏测试每组只有 2–3 段，
容量约束几乎没有可约束的空间，同时聚类误差还会带来损失。

## 4. 融合与后处理

- **加权对数概率求和**：`LOGIT += w · log p`，权重在按 prompt 分组的 OOF 上拟合。
  0.592 那一版的权重是 `W_SVC=1.021`、8B `w=0.226 / twin=0.079`、
  14B `w=0.429 / twin=0.150`——14B 的权重大于 8B，尽管两者单独分数相同（两者在 22% 的段上不一致）。
- **Sinkhorn 类别平衡**：目标为均匀 1/18，行归一化与列缩放交替 100 次，不用标签。
  作者报告本地约 **+0.5 分**（+0.005）。`len(test) < 50` 时跳过（交互态只有 3 行）。
- **互补栈混合**：新栈 85% + 旧四路 Gaussian 特征栈 15%，再走一次 Sinkhorn。

## 5. 与当前项目的逐项对照

| 环节 | 当前项目 | 公开最强 | 差距性质 |
|---|---|---|---|
| 表征 | 8B 冻结探针，**只取第 18 层** | 8B/14B LoRA（前 24/27 层），8 层池化 | **最大差距**：冻结探针 ≈ 0.48，两阶段 LoRA = 0.569 |
| 外部数据用法 | 4.4 万条**混入**单次训练（占 96%） | stage 1 单独预训练，stage 2 只用主办方数据 | **方向相反**，公开实测混入更差 |
| 中心化 | `center_mode=replace`（硬替换） | 按簇大小加权 `(n−1)/(n−1+2)` | 隐藏测试稀疏，硬替换会伤小簇 |
| 结构层 | PRISM（容量松弛指派，λ=2.0），本地 +0.144 | Gaussian 组头（解析积分），公开 +0.006；Hungarian 明确无收益 | **本地收益被高估**，因为本地每组 18 段 |
| 类别平衡 | 无（`em_prior` 已关） | Sinkhorn 100 步，+0.005 | 缺一个便宜的正收益项 |
| 融合 | L-BFGS 学权重，对数概率加权 | 同样 | 一致 |
| 家族专家 / 护盾 | 开启 | 报告"family gates 无收益" | 可能过拟合本地 396 行 |

## 6. 优先级建议

按"预期分数 / 工作量"排序：

1. **两阶段 LoRA（+0.08 ~ +0.14）**
   复用现有 `features/qwen_member.py` 的 QLoRA 路径与 5.5 万条语料，但把训练拆成两段：
   stage 1 只用外部语料（1 epoch，class-weighted），stage 2 只用 2,699 条主办方数据（2 epoch，lr 减半），
   **不混合**。同时把骨干截到前 24 层、池化改成 8 层拼接。
   这一步会把 OOF 从 0.42 推到 0.55 以上，是所有改动里唯一跨档的。

2. **中心化改为按簇大小加权（+0.02 ~ +0.05）**
   一行改动，且直接针对隐藏测试的稀疏结构。同时把 PRISM 从"硬容量约束"降级为
   "仅对 size ≥ 4 的簇生效、λ 收到 0.5"，或直接关闭。

3. **加 Sinkhorn（+0.005）**
   十行代码，无标签，风险低；只在 `len(test) ≥ 50` 时启用。

4. **公开语料按"符号一致性"再过滤一遍**
   现有 5.5 万条只做了 markdown/ASCII 过滤。补上"某符号在该模型训练样本中从未出现则丢弃"
   这条规则，能去掉一批伪特征，让 stage 1 学到的更接近真实风格。

5. **可以删的**：family experts、护盾、PRISM 的硬约束、seed 平均。它们本地有收益，
   但公开实测在真实 LB 上是零或负；在 396 行本地测试上拟合出来的 λ 尤其不可信。

## 7. 尚不确定的部分

- **0.650 与 0.607 怎么来的**：没有任何公开实现。讨论区最热的一条
  （"Will the winner just be whoever can get the most amount of extra training data?"，93 票）
  猜测答案是多得多的自生成数据；但帖子本身没有给出证据，无法证实。
- **稀疏测试集的结论是"探针推断"，不是官方披露**。它由两次提交的分数差反推，
  作者自己写了"读作有效组大小很小"而不是"每组恰好 2–3 段"。
  如果实际是"大量单例 + 少量完整组"，数值会接近，但组头的设计会不同。
- **两阶段 LoRA 的 0.569 是本地 5 折 CV**，与 LB 0.592（含融合）不同口径，不能逐项相加。
