# 后续优化路线（基于公开 0.636 方案）

日期：2026-10-23　｜　起点：Public **0.636**（复现中）　｜　榜单：1st 0.700，前 20 门槛 0.639

---

## 一、先看清一个事实：堆成员的边际收益已经趋近于零

把公开方案的三级阶梯摊开：

| 版本 | 成员数 | Public | 增量 |
|---|---|---|---|
| 0.620（nishantdahal 两阶段） | 4（SVC + 2 LoRA + DeBERTa） | 0.620 | — |
| 0.626（+2 编码器 + 排版守卫） | 6 | 0.626 | **+0.006** |
| 0.636（+12 成员互补栈 + ATLAS） | 18+ | 0.636 | **+0.010** |

**成员从 4 个加到 18 个，只买到 +0.016。** 而同一个 Qwen3-14B，只把池子从 35k 换到 83k，
单模就从 0.569 涨到 **0.611（+0.042）**。

结论：**继续加同类成员是负期望**。下一步必须让"某一个成员变强"，或者引入"新视角"。

要到 0.65（前十）需要 +0.014，到 0.665（前三）需要 +0.029，到 0.700 需要 +0.064。

---

## 二、六个方向（按 gain ÷ 成本 排序）

### P1 数据：池子扩容 + 清洗 —— 唯一被验证过能单点 +0.04 的手段

**原理**：18 类风格差异在 83k 段落上仍未饱和；旧池上四个不同骨干全是 0.569，说明瓶颈是数据不是容量。

**怎么做**
1. 把 `pool_v4.parquet`（75,783）与我们现有 55k 合并去重 → 目标 110k–130k；
2. 加两条公开验证过的过滤：
   - 剔除与任一 train 段落 **content-TF-IDF cos ≥ 0.3** 的样本（防 CV 虚高）；
   - 剔除单一来源的系统提示语料（文风与 host 不符）；
3. 段落级质量过滤：单词数 30–300、无 markdown、无重复、无 host 从不使用的标点。

**预期**：stage-1 head 在 host 上 0.49→0.57 这种量级；下游单模 +0.02~0.04。
**成本**：数据工程 1–2 天 + 一次 stage1 重训（2.5h GPU）。
**风险**：低。**这是我最建议先做的一件事。**

---

### P2 表征：把编码器从 1 个扩到 3–4 个，并把 max_len 提到 512

**原理**：双向编码器原样保留大小写、标点、空格、换行——解码器 tokenizer 会吃掉这些"排版指纹"。
公开证据：DeBERTa 0.546、ModernBERT 0.569、desklib 0.523，三者是**不同预训练目标**，错误相关性低。

**怎么做**
1. ModernBERT-large（8192 上下文，取 mean+cls 双池化）在扩容池上两阶段微调；
2. ELECTRA-large / desklib-detector 作为第三、第四视角（权重 0.05–0.10，只做纠错）；
3. **max_len 384 → 512**：host 段落 40–250 词，384 token 对长段落有截断，编码器尤其吃亏。

**预期**：每加一个正交编码器 +0.005~0.01；max_len 512 单独 +0.003~0.008。
**成本**：每个编码器 2–3h GPU（可用公开已微调权重省掉训练）。
**风险**：低—中（显存：编码器比 14B 便宜得多）。

---

### P3 决策层：直接对着 balanced accuracy 做后处理

**原理**：指标是**每类召回的平均**，类别不平衡会系统性压低少数类召回。Sinkhorn 是在"均匀边际"上做
近似，但它假设 18 类等量且只调一个标量族。

**怎么做**（三个都很便宜，可分别做 LB 探针）
1. **per-class log-bias**：18 个参数，在 OOF 上以"每类召回相等"为目标拟合（带 L2、prompt 分组 CV），
   比 Sinkhorn 更细；成本几分钟。
2. **Sinkhorn 超参扫描**：iters 100/300/1000、温度前置（P^(1/T) 再均衡）。
3. **twin 权重扫描**：0.05 / 0.10 / 0.15；聚类阈值 0.80 / 0.85 / 0.90。
   （隐藏集每 prompt 只有 2–3 段，twin 的实际作用面比 CV 大。）

**预期**：合计 +0.003~0.012。
**成本**：每次提交几十分钟。**风险**：低，但容易过拟合 LB 噪声——**一次只改一个**。

---

### P4 推理期免费增益：TTA

**原理**：同一段落的不同截断窗口携带互补信息，且不增加训练成本。

**怎么做**
1. **头尾双窗**：`text[:512]` 与 `text[-512:]` 各推一次，log-prob 平均；
2. 对编码器再加一个"段落切两半"的视图；
3. 只对低置信行做 TTA（省时间）。

**预期**：+0.003~0.008。
**成本**：推理时间 ×1.6，仍在 9h 内。**风险**：低。

---

### P5 骨干多样性：加第三、第四个解码器

**原理**：Qwen3-14B 与 Qwen2.5-14B 的 top-1 只有 77% 一致，说明"换家族"比"换尺寸"更能带来多样性。

**怎么做**
1. Qwen3-8B（24 层截断，公开 0.569）——便宜，且与 14B 判断相关但不同；
2. Qwen3-4B（style 池化）——极便宜，适合当"纠错票"；
3. 不同截断层数（27 vs 32 vs 36）当作"深度集成"。

**预期**：每个 +0.004~0.01（权重给小）。
**成本**：8B 约 1.5h 推理；4B 约 0.5h。**风险**：低。

---

### P6 转导学习：伪标签自训练（中高风险，但上限最高）

**原理**：隐藏测试 4,000 段是**无标签但同分布**的，且同一 prompt 的 2–3 段来自不同模型。
可以在推理期做一轮自训练，把测试集自身的结构用起来。

**怎么做**
1. 先用完整集成预测 test，取 top-30% 置信行作伪标签；
2. 只微调**线性头 / 最后一层 adapter**（不碰骨干），20–50 步；
3. 重新预测，与原预测做加权平均（0.7/0.3）。

**预期**：+0.005~0.015。
**成本**：+20–30 min 推理。**风险**：中高——伪标签一旦系统性偏移会放大；
必须先在 OOF 上模拟（用 host 的 20% 当"无标签集"）验证再上 LB。

## 三、明确不要碰（已被公开实测证伪）

| 方向 | 证据 |
|---|---|
| 簇内 Hungarian / "每模型至多一段" | public **0.558** vs local 0.723（同代码） |
| 更大骨干（旧池） | 8B/14B/7B/14B **全是 0.569** |
| seed 平均 / LoRA 权重平均 | ≤0.1 分 |
| Gemma-4-12B 换骨干 | 无提升 |
| 单家族专属判别器（family gates） | 无提升 |
| stage2 更多 epoch / 把池混回 stage2 | 更差 |
| 短窗口切分做 stage2 | 更差 |
| 用 stacker 替代固定权重 | 更差 |
| 继续加同类成员 | 12 个成员只买到 +0.010 |

---

## 四、实验协议（否则一定自欺）

1. **CV 必须 prompt 分组**，且池子先剔除与 train 近似（cos≥0.3）的段落；
2. **一次只改一个变量**，每次记一行：改动 / CV / LB / 结论；
3. **CV 涨但 LB 不涨的改动一律回滚**（公开方案就吃过 CV 0.642 → LB 0.620 的亏）；
4. LB 是 40% 切片，±0.003 以内视为噪声，不要据此调参；
5. 任何"结构性约束"先在 OOF 上做**反事实模拟**（关掉它对比），不要只看它开着时的分数。

## 六、诚实边界

- 0.636 → 0.700 的 0.064 差距，公开材料里**没有任何一条能解释**。榜首无公开实现，
  大概率是"更大的私有外料 + 更强的骨干/编码器"，而不是某个技巧。
- 上表的增益都是**基于公开数据点的外推**，不是实测。P1 的 +0.02~0.04 取决于新池的
  实际质量与去重率，可能显著低于预期。
- 到这个分数段，每次 +0.01 都需要 3–5 次提交验证；不要在单次结果上做重决策。
