## 一、#1 fleongg 0.636 —— 不做新训练，做推理期大融合

### 核心方法

```
主集成（0.620 那套，权重不动）
  ├─ SVC 1.0 / Qwen3-14B 0.4 / Qwen2.5-14B 0.2 / DeBERTa-v3-large 0.25
+ 15% 互补栈（12 个成员，全部复用公开权重，重跑推理）
+ 10% ATLAS（只作用于"不确定行"）
→ Sinkhorn 均衡 18 类
```

### 12 个互补成员（覆盖四类视角）

| 类别 | 成员 |
|---|---|
| 解码器线性头 | GLM4-9B(层 8,3)、Qwen3-8B(7,22)、Qwen2.5-7B(6,20)、Qwen3-4B(4,7 · style 池化) |
| **编码器线性头** | DeBERTa-v3-large(24,6)、ELECTRA-large(21,24)、desklib-detector(23) |
| LoRA（24 层截断） | Qwen3-24L ×3 个不同训练（public / seed7 / claude-head）、Qwen2.5-20L |
| 其它 | TokenAttention ×2、UltraBERT-380M、Gaussian 共享 prompt 头 ×4、StyleGram、stylometry-LGB |

### 关键技巧

1. **主链不动，只加"互补层"**：互补栈权重压到 15%，即使某个成员偏弱也不会伤主集成。
2. **ATLAS 只打不确定行**：source-conditioned likelihood 只对低置信行生效，等价于"定点纠错"而非全局改写。
3. **权重是圆整数字**：在 OOF 上定，不在 2,699 行上细调——因为细调 = 拟合噪声。
4. **每个成员必须真跑模型**，不允许用公开预测缓存（避免"复现即泄漏"）。
5. 工程上把 12 个成员的推理拆成独立模块 + 证据落盘（`comp_members.npz`），可逐成员归因。

### 优势 / 代价

- 优势：**风险最低、增益最确定**——不动已经验证过的主链，纯做加法。
- 代价：依赖 16 个公开数据集 + 8 个公开 kernel 权重，工程复杂度极高，任何人都能复现但很难改。

## 二、#2 mrpicklerick 0.627 —— 只调两个旋钮

### 核心方法

完整继承 0.624（两阶段 LoRA + Encoders + TypoGuard），改动仅两处：

```python
W_SVC      = 1.0
LORAS      = {"lora_qwen3_14b": w=0.4, twin_w=0.1, bs=8,
              "lora_qwen25_14b": w=0.2, twin_w=0.1, bs=8}
W_DEBERTA  = 0.25
OURS       = dict(modernbert=0.30, desklib=0.05)   # 6 : 1
TYPO_GUARDS = False                                 # 关掉排版守卫
```

1. **两个编码器的权重从 0.25 / 0.10 改成 0.30 / 0.05（6:1）**——ModernBERT 是强视角，desklib 与基础 DeBERTa 高度重叠，压到 1/6。
2. **关掉 TypoGuard**——实测守卫在隐藏集上是轻微负收益。

### 关键工程细节（值得直接抄）

| 细节 | 代码 | 作用 |
|---|---|---|
| fp32 累加 | `allow_fp16_reduced_precision_reduction = False` | T4 默认 fp16 累加会掉精度，深层模型尤其明显 |
| 双卡切分 | 权重 > 13 GiB 时 `device_map="auto", max_memory=13GiB×2` | 14B 单卡放不下时自动跨卡 |
| 去 final norm | `model.norm = nn.Identity()` | checkpoint 训练时就没有 final norm |
| 推理 bs | 8 | T4 上 14B + 8 层池化的安全值 |

### 优势 / 代价

- 优势：**每次提交只改一个变量**，分数变化可归因；成本极低（推理 15 分钟）。
- 代价：上限被底座锁死，只能在 0.62x 上做 ±0.005 的微调。

## 三、#3 nuridudak 0.626 —— 给解码器补"正交视角"

### 核心方法

0.620 底座 + 两个编码器成员 + 排版守卫：

| 增件 | 权重 | 证据 |
|---|---|---|
| **ModernBERT-large** | 0.25 | 两阶段微调（122k prompt-disjoint 外料 → 官方 train），**单模 OOF 0.569** |
| desklib DeBERTa-v3-large 检测器 | 0.10 | 同两阶段，OOF 0.523（与基础 DeBERTa 重叠，所以给小权重） |
| 排版守卫（Sinkhorn 之后） | — | 73.5k API 验证语料上违例率 ≤0.3% |

### 关键技巧

1. **编码器为什么有效**：双向编码器**原样保留大小写、标点、空格、制表/换行**，而解码器的 tokenizer 会把这些"排版指纹"吃掉。这是与 LoRA 解码器**正交**的视角，不是"再来一个更大的模型"。
2. **排版守卫是"排他"而非"改写"**：三条规则——spaced em-dash 只属于 Opus 4.6 / Opus 5 / GLM；弯撇号不属于 Claude / GLM；直双引号不属于 GPT-5.6 / GPT-6 / Qwen。**只在"当前 top 标签不可能"时才动手**，所以不会把对的改错。
3. **明确拒绝簇内 Hungarian**：作者自测同一套代码，加 Hungarian 后 public **0.558**，而不加时本地 **0.723**。这是公开材料里最硬的一条负结果。

### 优势 / 代价

- 优势：增量小、可插拔（"每个增件失败就跳过，保留基础融合"），且方向正确（正交视角）。
- 代价：需要额外训练一个编码器（122k 外料两阶段），不是纯推理能拿到的。

## 四、三套方案的共同共识

1. **数据 > 模型**：池子 35k → 83,827（26 个数据集）后，同一个 Qwen3-14B 从 0.569 → 0.611；
   只看 stage 1 之后、还没见 host 数据时，head 就从 0.493 → 0.572。
   反证：旧池上 Qwen3-8B / 14B / Qwen2.5-7B / 14B **四个骨干全是 0.569**——数据不足时加参数完全无效。
2. **融合 > 单模**：单模最好 0.611，融合 CV 0.642。
3. **固定权重 + Sinkhorn > 学习式 stacker / 结构化约束**：stacker 无效、簇内 Hungarian 大幅负收益。
4. **推理期复用公开权重** 比"自己从零训一个大模型"性价比高一个数量级（15 分钟 vs 6 小时）。

## 五、我们的差距（逐项、可量化）

| # | 维度 | 我们 | 前三名 | 差距/影响 |
|---|---|---|---|---|
| G1 | **预训练池** | 55,378 段（实际 stage1 用 35k 上限） | **83,827 段 / 26 个数据集**（SVC 用 75,783） | 同模型池子效应 **+0.042**（0.569→0.611） |
| G2 | **stage1 数据覆盖** | 三元组采样：35k 上限实际只前向 **19,272 样本（≈55%）**，45% 段落整轮没见过 | **全量 plain CE，100% 覆盖** | 估计 **+0.01~0.02**，且零额外算力（同样 epoch 更省） |
| G3 | **融合方式** | ridge 权重 + 温度 + EM 先验 + experts/shield + **PRISM** | 固定 log-prob 权重 + **Sinkhorn** | 我们 blend 0.5267 vs 单模 0.5238，**融合只加 0.003**；他们 0.611→0.642（+0.031） |
| G4 | **PRISM 簇内约束** | `prism.enabled: true, mode: relaxed, lam 0.5` | **明确不用**（public 0.558 vs local 0.723） | 极可能是**负资产**，且无法在 CV 上被发现 |
| G5 | **SVC 特征族** | linear_baseline **0.3489**（单视图） | 4 视图 TF-IDF + LinearSVC **0.473** | 成员差 **-0.124**，而 SVC 在他们融合里权重 1.0 |
| G6 | **编码器成员** | **无** | DeBERTa-v3-large 0.546 / ModernBERT 0.569 / desklib 0.523 | 少一整类正交视角，估计 **+0.015~0.03** |
| G7 | **骨干多样性** | 单骨干 8B-24L（0.5238） | 双骨干 14B-27L(0.611) + 14B-32L(0.569)，且二者仅 77% 一致 | 我们单模比对方 8B 旧池还低 **0.045** |
| G8 | **工程健壮性** | 无 `TINY` 守卫、无 OOM 重试、无 checkpoint 本地拷贝 | 三者都有（见 #2/#3） | 直接导致本次 **hidden rerun 抛异常、无分** |
| G9 | **战略** | 自训 6h → 单模 0.524 | 推理 15min → 融合 0.62 | 投入产出差约 **20×** |

### 关键诊断

- 我们单模 0.5238 比对方 **同尺寸 8B 在旧池上的 0.569 还低 0.045**。这说明差距不只是"池子小"，
  还有 **G2（覆盖 55%）** 与 **训练目标差异**（对方 stage1 是纯分类 CE，我们是三元组批次 + centred 辅助）。
- 我们融合只加 +0.003，而对方加 +0.031。原因不是融合算法不够花哨，而是**成员太弱**：
  stylegram 0.381 / linear 0.349 / stylometry 0.303 / ngram_lm 0.180，除了 qwen 之外没有能提供增益的成员。

## 六、优化方向与优先级

排序依据：**单位算力/工程量的期望增益**（gain per GPU-hour），并考虑风险。

| 优先级 | 动作 | 预期增益 | 成本 | 风险 |
|---|---|---|---|---|
| **P0** | 修提交链路：qwen 推理自适应 batch（OOM 减半重试到 1）+ `TINY` 守卫（3 行时用 train 行跑通 group/PRISM 路径）+ assemble 兜底（失败也写出合法 submission） | **从 0 到 0.52** | 2h 代码 + 1 次短 smoke | 低 |
| **P1** | stage1 改为**全量 plain class-weighted CE**（不再用三元组采样），上限提到全池 55k | **+0.02~0.04** | 同预算内（覆盖翻倍但 batch 变大，总前向 55k vs 19k） | 低 |
| **P2** | 用 **4 视图 TF-IDF + LinearSVC**（char 3-5 / word 1-3 / shape 2-6 / small-words 1-3）替换 `linear_baseline`，并在 train+pool 上拟合 | 成员 0.349→**0.45~0.47**，融合 **+0.01~0.02** | 10 分钟 CPU | 极低 |
| **P3** | **关掉 PRISM**（簇内约束），改固定 log-prob 权重 + Sinkhorn(300) | **+0.01~0.02**（主要是避免 LB 掉档） | 30 分钟 | 低 |
| **P4** | 加 **DeBERTa-v3-large 全参两阶段**（池 → train），作为编码器成员 | 单模 0.54 左右，融合 **+0.015~0.03** | ~2-3h GPU（需压缩 stage1 或减 fold） | 中（9h 预算紧） |
| **P5** | 加第二骨干 Qwen3-14B-27L（或 Qwen2.5-14B-32L）做多样性 | **+0.01~0.02** | 2.5× 单模成本（~6h），9h 内需砍 stage1 | 高（预算） |
| **P6** | 排版守卫（3 条，只在"标签不可能"时生效） | **+0.001~0.005** | 1h（需验证语料） | 低 |

### 推荐路线（按 9h 预算）

- **路线 A（稳，推荐先做）**：P0 → P1 → P2 → P3。
  预算：stage1 ~2.5h + stage2 ~1.5h + 古典/融合 ~0.5h ≈ **4.5h**，留足余量。
  预期：单模 0.55~0.57，融合 **0.56~0.58**。
- **路线 B（进取）**：A + P4（DeBERTa）。
  预算：需把 stage1 压到 2h、stage2 压到 1h，DeBERTa 占 2.5-3h，总 ≈ **7.5h**。
  预期：**0.58~0.60**。
- **路线 C（对标公开）**：B + P5。9h 内几乎不可能，除非 stage1 只用 20k 且 fold 减到 2。

### 不建议做的事

- 再加大骨干（旧池上 4 个骨干全 0.569，加参数无收益）；
- seed 平均、LoRA 权重平均（≤0.1 分）；
- 簇内"每模型至多一段"/Hungarian（public 0.558 vs local 0.723）；
- 用 stacker 替代固定权重；
- 把公开池混回 stage2。

## 七、两条纪律（避免再次踩坑）

1. **CV 必须诚实**：prompt 分组切分 + 剔除与 train 段落 content-TF-IDF 余弦 ≥0.3 的公开段落（对方剔了 1,153 条）。否则 CV ≈ 0.72 而 LB ≈ 0.56，正是 #3 作者踩过的坑。
2. **每次只改一个旋钮**：像 #2 那样，一次提交只动权重或只关守卫，才能把分数变化归因到具体改动。
