# 8 小时 QLoRA 扩容方案（T4 × 2）

> 代码：`src/ntl_pact18/features/qlora_head.py`、`features/qwen_member.py`（`mode: qlora`）
> 配置：`configs/kaggle_8h.yaml`　预算工具：`scripts/estimate_qlora_budget.py`
> 数据混合：`scripts/build_external_mix.py`

## 1. 为什么不是"换一个更大的模型"

这个任务只有 2,699 条训练文本、18 个类、每段 36–274 词。把骨干从 8B 换成 32B，增加的容量没有数据去喂，只会更快过拟合；而 T4 的 16 GB 显存也装不下 32B 的 4-bit 权重加优化器状态。

真正稀缺的不是参数，而是**判别性表征**：现有 probe 只取第 18 层、只做均值池化，而公开实验显示早期层（第 3 层）单独就有 0.391，第 18 层只有 0.327，六层拼接 0.414。所以扩容的方向是：

1. 让骨干**参与训练**（LoRA），而不只是读取冻结特征；
2. 让分类头**读取多个深度**，而不是最后一层；
3. 让损失**显式分离近亲模型**，而不只是逐样本交叉熵。

## 2. 整体架构

```
文本 (≤448 tok)
   └─ Qwen3-8B  4-bit NF4，冻结
        ├─ 36 层 decoder，每层挂 LoRA(r=32, α=64) 于 q/k/v/o/gate/up/down
        └─ 取 hidden_states[3,6,12,18,24,36]
              └─ 每层: Linear(4096→512) → tanh → 注意力打分 → 掩码 softmax → 加权池化
                    └─ concat(6×512) → LayerNorm → MLP(3072→512→18)
                          ├─ logits → CE(label_smoothing=0.05)
                          └─ 512 维融合向量 → SupCon(τ=0.07, 权重 0.1)
```

### 各模块作用

| 模块 | 作用 | 为什么这样选 |
|---|---|---|
| 4-bit NF4 冻结骨干 | 提供通用语言表征，显存从 16 GB 降到 ~5 GB | 2.7k 样本不足以全参微调；NF4 + 双量化是 T4 上唯一现实的选择 |
| LoRA r=32 全线性层 | 让注意力与 MLP 都适配本任务风格 | 只调 q/v 会欠拟合；r=16→32 的增量约 47M 参数，显存 +90 MB，但容量翻倍 |
| 多层注意力池化 | 每个深度学一个"看哪里"的权重 | 均值池化把功能词与内容词等同；注意力可聚焦标点、连接词等风格载体 |
| 6 层选择 | 覆盖 8%/17%/33%/50%/67%/100% 深度 | 早期层编码"怎么写"，深层编码"写什么"；只取一层必然偏科 |
| SupCon 辅助损失 | 同类拉近、异类推远 | 主要错误是兄弟模型（terra/sol、3.7/3.8 flash），CE 不直接优化类间间隔 |
| 标签平滑 0.05 | 抑制过度自信 | 标注本身有噪声（同一 prompt 下风格漂移） |

### 输入 / 输出 / 损失

- **输入**：token ids + attention mask，`max_len=448`（274 词约 380 token，留余量）。
- **输出**：18 维 logits；推理时 softmax 后作为 `qwen_qlora` 成员进入原有的温度缩放 / 融合 / 专家 / 护盾 / PRISM 链路。
- **损失**：`CE(logits, y, label_smoothing=0.05) + 0.1 × SupCon(fused, y, τ=0.07)`。
- **优化**：AdamW，lr 1e-4，weight decay 0.01，warmup 3%，cosine 衰减，梯度裁剪 1.0，梯度累积 8，梯度检查点开启。

## 3. 参数量与显存账

| 项 | 数量 | 说明 |
|---|---:|---|
| 骨干 | 8.2 B | 冻结，4-bit |
| LoRA | **94.4 M** | r=32 × 7 个投影 × 36 层 |
| 融合头 | **14.2 M** | 6 × (4096×512) + MLP |
| 可训练合计 | **108.6 M** | 占全模型 1.32% |
| 4-bit 权重 | ~5.0 GB | NF4 + double quant |
| LoRA + 头（fp16/fp32） | 0.19 + 0.06 GB | |
| AdamW 状态 | ~1.3 GB | 仅可训练参数 |
| 激活（检查点，B=1，448 tok） | ~1.5–2.5 GB | |
| **合计** | **~8–10 GB** | 16 GB 单卡有余量，可放到 batch=2 |

## 4. 时间预算：6 次训练，不是 5 次

`PACT18Pipeline.fit` 在 5 折 OOF 之后还会**全量重训一次**，所以 QLoRA 一共训练 **6 次**。这是最容易把 8 小时计划变成 10 小时的地方。

单次成本 ≈ `样本数 × 每样本秒数`。T4 上 8B 4-bit + LoRA + 检查点、448 token 的实测常数约 **1.0–1.2 s/样本**（需在目标机上用 20 步标定）。

| 方案 | 参数量 | 序列 | 每次样本 | 次数 | 预计时长 |
|---|---:|---:|---:|---:|---:|
| S0 probe（现状） | 8B | 384 | 2,699 | 1 | 0.16 h |
| S1 QLoRA r16，仅竞赛数据 | 8B | 384 | 2,159 | 6 | 3.4 h |
| S2 r32 + 外部 150/类 | 8B | 448 | 4,319 | 6 | 7.6 h |
| **S3 S2 + 融合头 + SupCon** | 8B | 448 | 4,319 | 6 | **8.0 h** |
| S3b 外部 200/类 | 8B | 448 | 5,039 | 6 | 9.3 h（超） |
| S4 换 14B | 14B | 448 | 4,319 | 6 | 14.0 h（超） |

`configs/kaggle_8h.yaml` 里 `time_budget_hours: 1.30` 是**每次 fit** 的上限，6 × 1.3 = 7.8 h，留 12 分钟给预测与保存；超时会在 epoch 中途停止，不会撑爆 9 小时。

## 5. 每次规模调整的依据

| 调整 | 依据 | 时长影响 |
|---|---|---|
| probe → QLoRA r16 | 冻结特征无法适配本任务；r16 是最小可行容量 | +3.2 h |
| r16 → r32 | r16 只覆盖注意力的低秩修正；r32 让 MLP 也参与，参数 47M→94M | +0.2 h（LoRA 计算占比很小） |
| 竞赛数据 → +150/类外部 | 2.7k 样本训 108M 参数必然过拟合；外部数据把每类扩到 300 | +4.1 h |
| 单层均值 → 6 层注意力 | 公开逐层实验：第 3 层 0.391 vs 第 18 层 0.327，拼接 0.414 | +0.4 h（池化本身极便宜） |
| 加 SupCon | 兄弟模型混淆是主要误差来源 | +0.0 h（复用同一前向） |
| 8B → 14B | 容量翻倍但样本不变，过拟合风险大于收益 | +6 h，且单卡 4-bit 只剩 ~3 GB 余量 |

## 6. 双卡怎么用

当前实现是**单卡训练**：`QwenMember.load()` 用 `device_map={"": 0}` 把 4-bit 权重钉在 0 号卡。T4 × 2 的第二张卡在这条链路里**不参与 QLoRA**，它承担的是同折内的 XGBoost / 其他成员，以及作为显存余量。

要真正吃满双卡，正确做法是 **fold-parallel**：两个进程各跑一部分折（GPU0 跑 0–2，GPU1 跑 3–4），最后合并 OOF 再拟合融合层。这能把 wall-clock 减半（8 h 预算可支持约 2× 计算量，例如 14B 或 2 epoch），但需要改 `pipeline.fit` 支持折子集与 OOF 合并，属于下一步工程，不在本次改动内。**不要用 DDP**：4-bit + LoRA 的 DDP 需要每卡一份量化权重，通信与显存都不划算。

## 7. 运行

```bash

```

## 8. 风险与限制

1. **bitsandbytes 仍缺失**：Kaggle 镜像没有它，必须把 cp313 manylinux wheel 放进数据集并 `pip install --no-index`，否则会自动退回 4 成员栈。
2. **过拟合**：108M 可训练参数对 5.4k 有效样本仍然偏大。1 epoch、标签平滑、dropout 0.05、早停（时间预算）是四道保险；若 OOF 明显低于 probe，先把 r 降到 16。
3. **时间常数为估计值**：1.0–1.2 s/样本需在 T4 上实测；若实测 1.4 s，S3 会变成 10 h，应把外部配额降到 100/类。
4. **保存体积**：`__getstate__` 把 LoRA + 头存成 numpy（约 450 MB），joblib 体积会明显变大；推理时会重建 4-bit 骨干并加载权重。
5. **折间不一致**：每折重新初始化 LoRA，折间方差大于 probe；融合权重会部分吸收这种方差，但 OOF 的置信度会略低。

## 9. 过拟合专项（108 M 参数 vs 5.4 k 样本）

### 9.1 先定义症状

OOF 是 prompt 分组的，所以过拟合会直接表现为**训练集 balanced accuracy 远高于 OOF**：

| 观察 | 含义 | 处理 |
|---|---|---|
| train BA 0.95+，OOF 0.40 左右 | 记住了 prompt/主题，没学到风格 | 降容量 + 加正则（本文件 9.2） |
| train BA 与 OOF 同步上升到 0.5 | 真在学习，容量不是瓶颈 | 保持容量，加数据或加层 |
| OOF 高但 test 低 | 折间不稳定或分布差异 | 多种子平均，检查外部数据域 |

判定阈值：`train BA - OOF BA > 0.25` 即视为过拟合，不要看 loss。

### 9.2 五道防线（按性价比排序）

| 优先级 | 措施 | 作用 | 代价 | 预期 |
|---|---|---|---|---|
| 1 | LoRA 只挂 q/k/v/o，r=32→16 | 可训练参数 94.4M→18.9M，去掉最嘈杂的 MLP 适配 | 几乎为零（前向不变） | 过拟合显著下降，OOF 常反升 |
| 2 | 内层 prompt 分组早停 | 在每折训练集内再留 15% prompt，按 BA 早停并回滚最优权重 | 每次 fit 多 ~4 min | 防止末段记忆，+0.01~0.02 |
| 3 | 标签平滑 0.05→0.1、LoRA dropout 0.05→0.1 | 抑制过度自信与适配器共适应 | 零 | +0.005~0.015 |
| 4 | lr 1e-4→5e-5、weight decay 0.01→0.05 | 减小适配器漂移 | 零 | 稳定性提升 |
| 5 | SupCon 权重 0.1→0.05 | 防止对比项在少样本上塌缩 | 零 | 稳定 |

配置见 `configs/kaggle_8h_reg.yaml`，与 `kaggle_8h.yaml` 只差上面这些项。

### 9.3 预算内的取舍：数据和容量不是对称的

QLoRA 的耗时由**前向/反向的样本数**决定，几乎与 LoRA 参数量无关。所以在 8 小时固定预算下：

- **减容量几乎不省时间**（r32→r16 省不到 5%），但能显著改善泛化；
- **加数据线性增加时间**（每类 +150 条 ≈ +4 h）；
- 想同时要“更多数据 + 更小容量”，只能减少折数：3 折 + 1 次重训 = 4 次 fit，可把外部配额提到 300/类而仍落在 8 h 内，代价是 OOF 更吵、融合权重更不稳。

### 9.4 代码开关

```yaml
features:
  qwen:
    lora_r: 16
    target_modules: [q_proj, k_proj, v_proj, o_proj]
    lora_dropout: 0.10
    label_smoothing: 0.10
    supcon_weight: 0.05
    lr: 0.00005
    weight_decay: 0.05
    val_fraction: 0.15          # 0 关闭早停
    early_stop_patience: 2
    eval_every: 100
```

早停只在**折内训练 prompt**上评估（`split_by_group`），不会碰该折的验证集；否则 OOF 会被污染，回滚的检查点也是按泄漏信息选的。

### 9.5 仍然不够时

- 把 `lora_r` 降到 8 并只挂 q/v（约 4.7M 可训练），先确认 OOF 能超过 probe 的 0.42；
- 用两个 r16 种子平均，通常优于单个 r32；
- 若 train/OOF 差距仍大，说明问题不在容量而在**特征**：外部数据的域与竞赛不一致，应回到数据侧做来源筛选，而不是继续压模型。
